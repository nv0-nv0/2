# VERIDION 시스템 제어면 고도화 최종 인수 보고서

## 최종 상태

- 제어면 버전: `system-control-plane-v1.1.0`
- 엔진: 56개
- 에이전트: 117개
- 이벤트 정책: 21개
- 운영 레이어: 10개
- 핵심 파이프라인: 12개
- 파이프라인 의존성: 15개
- 구조 blocker: 0개

## 핵심 변경

1. 플랫폼 기반 레이어에 `system-control-plane-engine`을 단일 책임 엔진으로 배정했습니다.
2. 모든 레이어가 하나 이상의 엔진을 갖도록 정리했습니다.
3. 12개 파이프라인에 책임 레이어, 선행 의존성, stale 기준, runbook ID를 연결했습니다.
4. 파이프라인 의존성 DAG의 알 수 없는 의존성, 순환, 중복 단계를 차단합니다.
5. 선행 파이프라인이 차단되면 후속 파이프라인에 상태가 전파됩니다.
6. 운영 이벤트 메모에 포함된 시크릿, Bearer 토큰, `nv0_` 계열 토큰, URL 자격증명을 저장 전에 마스킹합니다.
7. correlation ID 또는 동일 fingerprint 이벤트가 짧은 시간 안에 반복되면 중복 저장을 억제합니다.
8. 이벤트는 저장 순서가 아니라 생성 시각 기준으로 최신순 정렬합니다.
9. 활성 장애와 과거 장애 건수를 분리했습니다.
10. 관리자 콘솔에 레이어 상태, 최근 운영 이벤트, 의존성, fallback, 차단 전파, 구조 감사, 수동 새로고침, 30초 자동 갱신을 추가했습니다.

## 안전성

- 공개 API에는 운영 이벤트 메시지, 내부 파일 경로, 에이전트 상세를 노출하지 않습니다.
- 운영 이벤트 기록은 관리자 `ops.write` 권한과 기존 CSRF 보호를 유지합니다.
- MFA, TOTP, 상용 startup preflight, prelaunch safe hold 정책은 변경하지 않았습니다.

## 운영 인수 기준

1. `/api/admin/system-control-plane/audit` 점수가 100인지 확인합니다.
2. P0 파이프라인에 `blocked` 상태가 없는지 확인합니다.
3. 장애 기록 시 correlation ID를 함께 입력합니다.
4. 복구 후 같은 파이프라인에 `recovered` 또는 `healthy` 이벤트를 기록합니다.
5. 운영 메모에는 실제 키, 비밀번호, 토큰을 입력하지 않습니다.
