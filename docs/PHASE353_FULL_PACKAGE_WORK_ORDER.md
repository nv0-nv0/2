# PHASE353 전역 재검수·복구 작업지시서

## 1. 현재 판단

- 작업 모드: REVIEW → STABLE → COMMERCIAL
- 목표: VERIDION 고객용 진단 흐름을 보존하면서 실제 납품 명령, 보안 격리, 공개 응답, QA 계약, 문서와 환경변수 예시를 하나의 최신 릴리즈 게이트로 통합한다.
- 보존할 핵심 방향: 홈은 목적 설명과 단일 진단 화면 이동에 집중한다. 실제 URL 진단은 `/products/veridion/demo`에서 수행한다. 고객 화면과 내부 운영 API를 분리한다.

## 2. 변경 위험도

- 위험도: 중간 이하
- 데이터 변경: 없음
- DB 마이그레이션: 없음
- 결제 로직 변경: 없음
- 인증 구조 변경: 없음
- 롤백: `/mnt/data/veridion_phase353_rollback`의 변경 전 사본으로 파일 단위 복원 가능

## 3. 구현 범위

1. 최신 홈·진단·포털 구조와 구형 QA 계약의 불일치 수정
2. 고객 공개 응답에서 내부 용어 제거 시 문구 훼손 방지
3. 공개 설정 API를 고객용 최소 빌드 식별 정보로 축소
4. 내부 운영 API 30개 고객 공개 차단 복구
5. 내부 운영 API 테스트는 `NODE_ENV=test`와 명시 플래그가 모두 있을 때만 허용
6. 공개 제품 파이프라인 검사 독립 실행 지원
7. 루트 환경변수 예시와 Coolify 예시 보강
8. PHASE353 전역 감사와 최종 릴리즈 게이트 추가
9. 납품·사전배포·원클릭 테스트 진입점을 PHASE353으로 통일

## 4. 제외 범위

- 실제 `nv0.kr` 운영 서버 배포
- 외부 API 키 입력
- 실결제 사업자 승인 및 운영 웹훅 실검증
- 운영 DNS·Coolify 환경 실검증

## 5. 완료 기준

- `npm run phase353:final` 통과
- `npm run delivery:final`이 PHASE353 최종 게이트 호출
- `npm run release:predeploy`가 PHASE353 최종 게이트 호출
- `./RUN_ALL_TESTS.sh`가 PHASE353 최종 게이트 호출
- 고객 공개 API 격리 검사 통과
- 전역 감사 보고서 생성
- 잔여 외부 환경 의존 항목을 미실행으로 명확히 기록
