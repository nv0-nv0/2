# PHASE103 최종 인수검증 및 개발 작업 지시서

## 1. 문제 정의

목표는 `nv0_phase102_interim_delivery_20260426` 패키지를 기준으로 미완성·잔여·검증 누락 항목을 제거하고, 개발자·PM·배포 담당자가 즉시 인수 가능한 100점 납품 패키지 상태로 고정하는 것이다.

## 2. 원인 가설

### 확인된 원인

- `npm test` 최초 실행 결과 88개 중 86개 통과, 2개 실패가 발생했다.
- 실패 항목은 `runtime/uploads`와 `runtime/backups` 디렉터리에 테스트 산출물이 남아 있어 릴리즈 게이트의 runtime clean 조건을 위반한 것이다.
- 기능 코드 실패가 아니라 납품 패키지 정리 누락이다.

### [가정]

- 해당 runtime 파일은 이전 검증 과정에서 생성된 임시 업로드 파일과 백업 파일이다.
- 실제 운영 데이터로 확인되지 않았으므로 납품 패키지에는 포함하지 않는 것을 기본값으로 한다.

### [확인 필요]

- 운영 서버에 이미 배포된 실제 runtime 데이터가 있다면 삭제 대상이 아니다.
- 운영 환경에서는 배포 전 별도 백업을 먼저 수행해야 한다.

## 3. 수정 범위

### 완료 처리

- `runtime/uploads/*` 임시 업로드 파일 제거
- `runtime/backups/*` 임시 백업 파일 제거
- `npm test` 재실행
- `ci:strict` 재실행
- Phase76 보안 라우팅 검증
- Phase77 가시성 통합 검증
- Phase100 시각 접근성 검증
- 최종 인수검증 문서 추가

### 수정 제외

- 기능 로직 변경 없음
- DB 스키마 변경 없음
- API 계약 변경 없음
- 환경변수 값 변경 없음

## 4. 구현 단계

1. 패키지 압축을 해제한다.
2. `site` 루트에서 테스트를 실행한다.
3. 실패 항목을 확인한다.
4. `runtime/uploads`와 `runtime/backups`의 임시 산출물을 제거한다.
5. 전체 테스트를 다시 실행한다.
6. CI strict 게이트를 실행한다.
7. 보안·가시성·접근성 검증을 실행한다.
8. 최종 납품 패키지를 재압축한다.

## 6. 예외 처리

- 운영 데이터가 `runtime/uploads` 또는 `runtime/backups`에 있는 경우 삭제하지 않는다.
- 운영 반영 전 `npm run backup:runtime` 또는 서버 스냅샷을 먼저 수행한다.
- 환경변수는 `.env.example`, `deploy/*.example`, Coolify 설정값을 기준으로 운영자가 직접 확정한다.
- 테스트 실패가 다시 발생하면 실패 항목명을 기준으로 기능 문제와 패키징 문제를 분리한다.

## 7. 롤백 기준

### 즉시 롤백 조건

- 배포 후 `/healthz` 또는 `/readyz` 실패
- 로그인·주문·문서·관리자 콘솔 등 핵심 플로우 실패
- 5xx 오류 지속 발생
- 업로드·백업·세션 데이터 손상 징후 발생
- Cloudflare 캐시 제거 후에도 이전 빌드가 지속 노출

### 롤백 절차

1. 직전 정상 패키지 또는 서버 스냅샷으로 복구한다.
2. Coolify 배포 이력을 기준으로 이전 성공 배포본을 재활성화한다.
3. Cloudflare Cache Purge를 수행한다.
4. `/healthz`, `/readyz`, `/`, `/plans`, `/checkout`, `/portal`, `/admin`을 재검증한다.
5. 실패 원인을 별도 브랜치에서 수정한다.
