# PHASE357 전역 QA·접근성·보안·런타임 격리 마감

PHASE356 전환 위기도 대시보드를 유지하면서 전체 패키지를 공개 화면, 관리자 화면, API, 보안, 배포, 런타임, 테스트 격리, 문서, 인수 러너 관점에서 다시 감사했다. 단순 게이트 재실행에 그치지 않고 기존 검증이 놓친 실제 운영 결함과 역사적 계약 충돌을 찾아 수정했다.

## 핵심 결과

- 관리자 7개 화면 본문 바로가기 추가
- 무료 진단 2개 경로와 결제 폼의 키보드 Enter 실행 보강
- 진단 결과 포커스 이동과 live region 보강
- 고객 포털 사이드 메뉴 접근 가능한 이름 추가
- boot-safe Compose 2개의 운영값 전달을 각각 137개 키로 통일
- 운영 템플릿 5개의 역할과 키 정합성 보강
- 공개 진단 입력 단계에서 루프백·사설 IP·메타데이터 주소 fail-closed 차단
- SSRF 차단 대상 9개와 정상 공개 URL 1개 동적 회귀 테스트 추가
- 공개 차단 운영 API 30개 격리 유지
- 독립 테스트가 `runtime-test-*` 또는 루트 runtime을 남기지 않도록 정리 책임 보강
- PortOne 테스트의 `process.exit(0)` 실패 은폐 가능성 제거
- `NV0_RUNTIME_DIR` 외부 경로 사용 시 업로드 다운로드 404가 발생하는 실제 결함 수정
- 런타임 백업·복구·업로드 보존 검사를 외부 임시 런타임에서 재검증
- 로컬 `.env.example`과 상용 배포 템플릿의 역할 분리
- acceptance 러너를 seed 기반 clean delivery와 production-shape 환경 기준으로 갱신
- acceptance 28/28, PHASE357 최종 게이트 12/12 통과

## 원자 보완 항목

중복 제거 기준 **105개**를 실제 처리했다. 상세 내역은 `PHASE357_REMEDIATION_MATRIX.md`에서 확인한다.

## 데이터 영향

DB 스키마, 기존 데이터 구조, 결제 처리 로직, 인증 권한 모델은 변경하지 않았다. 배송 ZIP에는 활성 DB, 세션, 보안 레코드, 업로드, 백업, `runtime-test-*`를 포함하지 않고 초기 seed만 유지한다.

## 실제 기능 수정

`NV0_RUNTIME_DIR`을 기본 경로가 아닌 외부 경로로 설정하면 업로드 저장은 성공하지만 다운로드 라우트가 저장 위치를 따라가지 못해 404가 발생했다. `server/index.mjs`에서 `/runtime/uploads/`를 실제 `UPLOADS_DIR` 기준으로 안전하게 제공하도록 수정했다. 기존 경로 이탈 방지 검사는 유지했다.

## 운영 환경 확인 필요

실제 서버 배포, DNS, Docker 컨테이너 빌드·기동, Coolify 환경변수 주입, 실결제 웹훅, 공개 사업자 정보 정확성은 운영 환경에서 별도로 확인한다. 로컬 패키지 통과와 운영 반영 완료는 구분한다.


## CSP 시각화 무결성 후속 패치

추가 적대적 검수에서 서버가 `style-src 'self'` CSP를 유지하는 반면 무료 진단 결과의 진행 막대, 원형 위기도 그래프, 영역별 막대가 동적 `style=` 속성을 사용한다는 충돌을 확인했다. CSP를 완화하지 않고 0~100 구간 클래스와 공통 폭 유틸리티로 교체했다. 재발 방지를 위해 `npm run check:csp-inline-style` 계약을 최신 릴리즈 게이트에 연결했다.
