# 운영 모니터링 및 롤백 런북

## 목적
배포 후 장애가 발생했을 때 공개 진단, 결제, 게시판, 내 사이트 관리 흐름을 빠르게 복구한다.

## 감시 기준
- `/healthz`가 실패하면 서버 프로세스와 런타임 저장소를 먼저 확인한다.
- `/readyz`가 실패하면 DB, Redis, S3/R2, 설정값을 확인한다.
- 공개 핵심 페이지가 5xx를 반환하면 직전 배포본으로 롤백한다.
- 결제 웹훅 실패가 반복되면 결제 제공자를 일시 차단하고 주문 상태를 수동 확인한다.
- 자동발행 실패가 반복되면 게시판 공개 동기화를 중단하지 않고 실패 사유만 감사 로그에 남긴다.

## 롤백 순서
1. 새 배포 캐시를 비운다.
2. 직전 ZIP 또는 이미지 태그로 되돌린다.
3. `npm run verify:prod`로 공개 페이지와 관리자 보호 흐름을 확인한다.
4. `npm run backup:runtime`으로 현재 런타임을 보존한다.
5. 필요한 경우 `npm run restore:latest`로 마지막 정상 백업을 복구한다.
6. 알림 수신자에게 장애 원인과 복구 완료 시간을 공유한다.

## 최종 게이트
- `npm run monitoring:rollback`
- `npm run restore:drill`
- `npm run verify:prod`
