# Phase106 모니터링 및 자동 롤백 운영 런북

## 목적

선택사항까지 포함하여 비어 있는 영역 재발을 막고, 배포 후 장애가 감지되면 운영자가 즉시 이전 정상 버전으로 복구할 수 있는 기준을 고정한다.

## 감지 대상

| 구분 | 감지 기준 | 조치 |
|---|---|---|
| Health | `/health` 또는 `verify:prod` 실패 | 배포 중단 후 직전 버전 확인 |
| 핵심 플로우 | 진단, 저장, 결제, 관리자 조회 실패 | 신규 배포 격리 |
| 서버 오류 | 5xx 반복 발생 | 로그 확보 후 롤백 |
| 콘텐츠 완성도 | completeness 또는 AST guard 실패 | 배포 차단 |
| 런타임 데이터 | 백업/복구 검증 실패 | 데이터 변경 작업 중단 |

## 자동 롤백 기준

다음 중 하나라도 발생하면 롤백 후보로 판정한다.

1. 배포 직후 핵심 페이지 접근 실패
2. API 상태 확인 실패
3. `npm run verify:prod` 실패
4. `npm run check:ast-placeholder` 실패
5. `npm run review:local-ai` 실패
6. `npm run monitor:rollback-gate` 실패
7. 결제·저장·로그인·관리자 조회 중 하나라도 실패

## 복구 절차

1. 신규 배포 버전을 중지한다.
2. 직전 정상 아티팩트로 복구한다.
3. `npm run restore:latest`로 런타임 복구 가능성을 확인한다.
4. 캐시를 무효화한다.
5. `npm run verify:prod`를 실행한다.
6. `npm run phase106:final`을 재실행한다.
7. 원인 분석 결과를 별도 문서로 남긴다.

## 운영자 확인 항목

- [ ] 직전 정상 버전 식별 완료
- [ ] 런타임 백업 존재 확인
- [ ] 환경변수 변경 여부 확인
- [ ] DB 마이그레이션 여부 확인
- [ ] 캐시 무효화 완료
- [ ] 핵심 플로우 재검증 완료

## 완료 기준

롤백 후 핵심 페이지, API, 관리자 화면, 저장/조회 흐름이 모두 정상이어야 한다. 확인되지 않은 장애 원인은 단정하지 않고 별도 재현 태스크로 분리한다.
