# PHASE314 유료 서비스 정밀 설계 회의록

## 1. 회의 목적
VERIDION의 유료 서비스가 결제 화면 문구 수준이 아니라 실제 운영 흐름에서 정확히 동작하도록 상품, 결제, 동의, 권한, 산출물, 환불, 관리자 운영, 법률 증적을 하나의 상태 모델로 고정한다.

## 2. 결론
유료 기능은 `provider_verified_paid` 이전에는 절대 열리지 않는다. 클라이언트는 이메일, 대상 사이트, 필수 동의, 결제창 호출만 담당하고 가격, 주문, 결제 확정, 산출물 생성, 접근 권한은 서버가 통제한다.

## 3. 상품 구조

| 상품 | 과금 | 가격 | 대상 | 실제 제공 | 접근 기간 | 갱신 |
|---|---:|---:|---|---|---:|---|
| 무료 진단 | 무료 | 0원 | 사전 점검 사용자 | 공개 URL 요약 점검 | 즉시 화면 | 없음 |
| 기본 리포트 | 1회 결제 | 49,000원 | 단일 사이트 상세 확인 | PDF, 대시보드, 근거 요약, 체크리스트 | 90일 | 없음 |
| 전문가 플랜 | 30일 이용권 | 149,000원 | 정기 점검·운영 개선 사용자 | 전문가 보강, 정기 재점검 가이드, 포털 관리 | 30일 | 자동정기결제 구현 전까지 수동 갱신 |

## 4. 실제 동작 상태

1. 사용자가 무료 진단 또는 결제 화면에서 대상 사이트 URL을 확정한다.
2. 서버가 상품 카탈로그에서 가격과 제공 범위를 잠근다.
3. 사용자가 개인정보처리방침, 이용약관, 환불정책, 디지털 산출물 제공 고지를 확인한다.
4. 서버가 주문과 결제 세션을 생성한다.
5. PortOne 또는 외부 결제사가 결제를 처리한다.
6. 서버는 클라이언트 응답만 믿지 않고 결제사 조회 또는 검증된 웹훅으로 금액, 상태, 주문번호를 재검증한다.
7. 상태가 `paid`가 된 주문만 산출물 생성과 다운로드 접근을 얻는다.
8. 비회원 주문은 accessToken 또는 소유 계정 세션 없이는 주문, 포털, 산출물 조회가 불가능하다.
9. 전문가 플랜은 subscription billing이 확정되기 전까지 자동정기결제로 표시하지 않는다.
10. 환불 요청은 주문 상태, 제공 상태, 중복 요청, 정책 버전을 기준으로 검토 큐에 들어간다.

## 5. 필수 차단 규칙

- 대상 사이트 없는 유료 결제 차단
- Free 상품 checkout-session 차단
- 클라이언트 전달 금액 무시
- 결제사 검증 전 paid unlock 차단
- orderId 단독 주문 조회 차단
- orderId 단독 포털 접근 차단
- orderId 단독 산출물 조회 차단
- 미결제 다운로드 차단
- Report 구매를 구독 활성화로 처리하지 않음
- Expert를 자동정기결제로 오인시키는 문구 차단

## 7. 운영 전 확인

운영 서버에서는 결제 제공자 실키, 웹훅 secret, 사업자 정보, 정책 문서, 개인정보 보호책임자, 환불 처리자 권한, 운영 DB/Redis/S3 연결을 확인해야 한다. 법률 리스크를 0으로 보장할 수는 없으므로 실제 문구와 정책은 전문가 검토 후 고정한다.
