# PHASE357 전역 QA·접근성·보안·런타임 격리 작업지시서

## 목표

PHASE356 전환 위기도 대시보드를 유지하면서 전체 패키지를 공개 화면, 관리자 화면, 키보드 조작, 상태 UI, API, SSRF 방어, 업로드 제공, Compose 전달값, 운영 템플릿, 테스트 격리, 인수 러너, 배송 런타임 기준으로 다시 감사한다.

## 적용 범위

- 관리자 화면 7개 접근성 진입점
- 무료 진단 폼 2개 경로와 공통 렌더러
- 결제 폼과 결제 상태 UI
- 고객 포털 사이드 메뉴
- 공개 진단 URL 입력 fail-closed SSRF 방어
- 외부 `NV0_RUNTIME_DIR` 업로드 저장·다운로드·재시작·복구
- boot-safe Compose 2개와 환경변수 템플릿 5개
- 결제·TrustOps·스모크·과거 인수 테스트의 임시 런타임 격리
- 로컬 개발 예시와 상용 production-shape 환경의 역할 분리
- acceptance 28단계와 PHASE357 전용 계약·감사·최종 게이트

## 제외 범위

- DB 스키마 변경
- 데이터 마이그레이션
- 결제 공급자 실계정 연결
- 운영 서버 배포
- DNS 변경
- Docker 엔진이 필요한 실제 컨테이너 기동

## 위험도

중간. 기존 데이터 스키마와 결제 처리 로직은 유지하지만 공개 URL 입력 검증, 업로드 제공 라우트, 테스트 런타임 경로, 배포 환경 검증을 수정한다. 각 변경은 전용 회귀 테스트와 전체 게이트로 검증한다.

## 롤백

문제가 발생하면 PHASE356 ZIP으로 복귀하고 `npm run phase356:final`을 실행한다. PHASE357은 데이터 마이그레이션을 포함하지 않는다.
