# Phase21 100점 선언 전 최종 QA / 하드닝 보고서

## 목적
Phase20 패키지를 기준으로 “뚝딱 추가한 기능” 수준이 아니라 실제 상용 운영 전 코드·라우트·런타임·상품화·결제 후 산출물 흐름을 다시 점검하고, 오류 은폐와 런타임 찌꺼기를 제거하는 것을 목표로 재검수했습니다.

## 수정/보강 항목

1. `package.json`의 `test:all`, `ci:strict`에서 실패를 숨기던 `; exit 0` 제거
2. 릴리스 패키지에 테스트 중 생성된 업로드/백업/리포트 파일이 포함되지 않도록 런타임 클린 검사 추가
3. `runtime/data/db.json`을 `db.seed.json`과 동일하게 정리
4. `runtime/data/sessions.json`을 빈 배열로 초기화
5. 정적 페이지, 링크, 렌더링 안전성, 상품 카탈로그, 배포 번들, 상용 런타임 환경 검증 재실행
6. 실제 서버 기동 후 `/readyz`, 공개 페이지, 상품 API, 스캔, 체크아웃, 결제 완료, 산출물 조회 흐름을 수동 스모크 검증
7. Phase21 테스트 결과 파일과 최종 납품 기준을 문서화

## 상용 운영 전 필수 외부 확인

코드 패키지 내부 검증은 완료했지만, 아래는 실제 운영 인프라 값이 있어야 최종 확인 가능합니다.

- Coolify 실제 `No Cache Redeploy`
- Cloudflare `Purge Everything`
- 운영 PostgreSQL 연결
- 운영 Redis 연결
- PortOne 운영 키/웹훅 검증
- Cloudflare Turnstile 운영 키
- Object Storage/S3 운영 버킷 권한

## 최종 판정

Phase21 패키지는 코드 내부 기준으로 이전 패키지보다 더 엄격한 검증 기준을 통과했습니다. 다만 실제 운영 인프라 키와 외부 결제/저장소/DB/Redis 연결은 배포 환경에서 별도 확인해야 합니다.
